# 绿城中国经营驾驶舱指标与数据需求说明

> 版本：v0.1（业务评审稿）  
> 编制日期：2026-09-16  
> 对应代码：`feature-hcx` / `85a640c`  
> 适用页面：1920 × 960「绿城中国经营驾驶舱」  
> 当前状态：完成代码现状盘点，待各业务数据责任人确认口径与权威来源

## 1. 文档目的

本文件用于统一大屏的指标名称、当前展示值、单位、时间口径、数据粒度、来源与校验要求，可同时作为：

- 业务部门确认指标口径的评审底稿；
- 数据团队准备数据集、接口和质量规则的需求清单；
- 前端团队绑定数据、处理空值和展示格式的依据；
- 测试与验收团队逐项核数的检查表。

本文件记录的是**当前代码基线中的展示快照与已知数据链路**，不是对生产经营数据的最终审计结论。未获得权威系统、SQL/接口结果或业务签字确认的项目，统一标记为“待确认”。

## 2. 大屏范围与信息架构

大屏分为三部分：

1. **左侧｜重资产项目**：投资与土储、销售去化、项目交付、结转资源、开发效率；
2. **中部｜经营地图**：集团/区域切换、城市项目分布、全国覆盖统计、城市项目下钻；
3. **右侧｜特色业务**：代建、商管、小镇、生活科技、康养。

按业务语义清点，当前需要维护约 **50 项标量指标**，另有 1 组月度趋势序列、1 组产业分类、城市/项目明细以及 4 条项目或荣誉文案。左侧“客户评价”模块已从当前页面移除，不列入当前展示范围；其原始指标仍保留在代码中，见第 9 节。

## 3. 数据状态分级

| 级别 | 含义 | 当前实现 | 使用要求 |
|---|---|---|---|
| A｜动态数据 | 页面打开时从经营数据集实时/准实时查询 | 本地开发服务通过 `/api/latest-sales`、`/api/operating-overview` 查询；仅开发态中间件实现 | 生产发布前必须补齐可部署的数据服务、鉴权、超时和监控 |
| B｜经营快照 | 从经营指挥/问数数据集中提取后固化在代码 | `wenshu-*.ts` 与面板内快照常量 | 必须显示快照日期；过期后人工或任务刷新 |
| C｜披露/业务静态值 | 半年报材料或业务方提供的固定值 | `half-year-2026-metrics.ts` | 按披露周期更新；不得与滚动值混为同一时点 |
| D｜说明性文本 | 项目案例、荣誉、市占率说明等 | 代码静态文案 | 需记录生效日期、出处、到期/撤下条件 |

### 5.2 区域/行政范围派生指标

选择经营组织时，需要以下字段：

- `totalProjects`：组织项目数；
- `soilAreaM2`：土储总建面（平方米，展示前转万㎡）；
- `constructionProjects`、`constructionAreaM2`：在建项目数与建面；
- `pendingProjects`、`pendingAreaM2`：纯待开发项目数与未开发建面；
- `cities[]`：组织覆盖城市及每城上述指标。

选择省/市行政范围时，由项目明细派生：

- 境内项目数、覆盖城市数；
- 项目总建面；
- 在建及待开发项目数、总建面；
- 城市合同销售额（A：6286 动态查询；B：失败时回退 6283 城市快照）；省级范围当前仅能汇总 6283 快照，且不提供省级月度趋势。

## 7. 建议统一的数据合同

所有指标建议统一成以下结构，禁止把“+”“Top 4”“截至日期”混进数值或单位字段：

```ts
type CockpitMetric = {
  id: string;
  canonicalName: string;
  displayName: string;
  value: number | null;
  displayValue?: string;
  canonicalUnit: "count" | "household" | "city" | "area_sqm" | "currency_cny" | "people" | "visits" | "sets" | "beds" | "ratio" | "score" | "month";
  displayUnit: "个" | "户" | "座" | "城" | "项" | "万㎡" | "万方" | "亿元" | "亿" | "万人" | "万人次" | "万套" | "万床" | "%" | "分" | "月";
  qualifier?: "+" | "约" | "近";
  comparison?: string;
  periodType: "point" | "ytd" | "month" | "half-year" | "full-year" | "cumulative" | "plan";
  periodStart?: string;
  periodEnd: string;
  scopeType: "group" | "organization" | "province" | "city" | "project";
  scopeCode: string;
  sourceSystem: string;
  sourceDataset?: string;
  sourceField?: string;
  evidenceStatus: "unverified-code" | "verified-source" | "business-approved";
  refreshedAt: string;
  status: "ready" | "stale" | "unavailable" | "error";
};
```

项目/荣誉文案建议另建 `CockpitHighlight`，至少包含类型、标题、关联项目/业务、发生日期、来源、有效期和排序，不再塞进数值指标数组。

## 8. 展示与数据质量规则

### 8.1 展示规则

- 空值显示“—”，不能用 `0` 代替未知值；
- 金额默认保留 0–2 位小数，面积默认保留 0–2 位小数，比例默认 1 位小数；
- 千分位仅用于四位及以上数值；
- “+”“约”“近”进入 `qualifier`，Top 排名进入 `comparison`；
- 同一屏混合 H1、年度、滚动快照时，每个模块必须带周期或快照日期；
- 面积单位统一优先使用“万㎡”，“万方”仅在业务明确要求时作为展示别名；
- 地图标签展示的是项目数量，不得暗示标签坐标是项目精确地址。

### 8.2 自动质量校验

1. 指标 ID 在全局唯一，名称、单位和范围不可随接口响应漂移；
2. 同源 6286 的累计销售额与月度销售额合计差异不超过 0.05 亿元；10266 与 6286 跨源对比单独记录差异并按批准阈值告警；
3. 一二线新增货值 ≤ 全部新增货值，占比位于 0–100%；
4. 项目数、户数、城市数、荣誉数必须为非负整数；
5. 满意度、入住率、目标进度位于 0–100；
6. 面积、金额不得为负；月度销售冲销值可为负，但必须有数据状态说明；
7. 结转分期合计与已售未结总额差异不超过披露取整容差；
8. 快照超过约定 SLA 后标记 `stale`，不继续伪装为最新值；
9. 接口失败时可以回退静态快照，但必须保留真实的 `periodEnd/sourceSystem/status`；
10. 不同范围（集团、组织、行政区、城市）的值不得在前端直接相加。

## 9. 已发现的口径冲突与风险

| 优先级 | 风险 | 影响 | 建议处理 |
|---|---|---|---|
| P0 | 本地动态接口仅在 `vite.config.ts` 的开发服务器中实现，生产 Worker 未实现同等路由 | 线上无法持续获取最新经营数据，只能依赖静态回退 | 将数据访问迁移到可部署的服务端路由/BFF，并补鉴权与监控 |
| P0 | 当前发布环境回退静态快照，但卡面仍使用“动态销售”等文案，且快照日期大多只存在于代码属性中 | 用户可能把历史快照误认作实时数据 | 静态模式改为“销售快照”，卡面可见地显示截至日期和数据状态 |
| P0 | 代建 7 项缺独立原始页码/系统字段，市占率缺分母 | 无法核数和解释 | 由代建业务负责人补齐出处、公式、统计机构并签字 |
| P0 | 512、510、488 三个项目数并存 | 容易被误认为同一指标不一致 | 分别命名为“未注销项目”“经营组织项目”“地图境内项目”，展示日期和排除规则 |
| P1 | 代码基线累计销售额 642.09 亿元（10266 快照）与 1–8 月趋势合计 643.04 亿元（6286 快照）相差 0.95 亿元 | 跨数据集无法通过 0.05 亿元同源校验 | 明确 10266/6286 的范围和冲销规则；在未对齐前标记跨源差异而非判为前端算错 |
| P1 | 滚动新增货值/销售额使用 H1 的 Top 排名标签 | 排名与数值时点不一致 | 排名仅绑定披露值，或接入同日行业排名数据 |
| P1 | 项目动态与 3002 快照的土储、在建面积不同 | 业务质疑数字 | 展示快照日期；确定一个权威口径，其余仅用于下钻 |
| P1 | 右侧特色业务均为静态值且无 `asOfDate` | 无法判断是否过期 | 每个业务组增加 `periodEnd/refreshedAt/owner` |
| P1 | 小镇产业分类被放在数值 facts 中且 `numericValue=5` | 可能被错误聚合为 KPI | 抽为维度数组，不参与 KPI 统计 |
| P1 | 小镇字段 ID 与当前名称不一致 | 接口映射和维护易出错 | 重命名字段并保留一次兼容迁移 |
| P2 | 面积单位“万方/万㎡”、修饰符位置不统一 | 视觉和数据解析不一致 | 统一数据单位与展示格式器 |
| P2 | 商管/小镇/康养模型名称与 UI 名称双轨 | 报表与接口对接歧义 | 同时保留 canonical name 与 display name |
| P2 | 项目/荣誉文案无日期、机构和有效期 | 文案过期后仍展示 | 建文案台账并设置季度复核 |
