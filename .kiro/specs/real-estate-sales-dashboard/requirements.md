# 房地产销售看板需求文档

## 1. 文档目的
基于当前已实现的前端页面与交互，沉淀一份可用于后续迭代、测试验收和联调的需求基线文档。

## 2. 产品范围
本需求覆盖两类页面：
- 集团看板页（Dashboard）
- 项目详情页（Project Detail）

当前版本使用本地 Mock 数据，不包含后端 API 对接、权限体系和真实鉴权。

## 3. 业务目标
- 支持销售管理人员快速查看集团与项目销售表现。
- 支持通过周期、业态、口径、分类和户型进行多维筛选。
- 支持从集团看板下钻到项目详情，并在详情页进行进一步分析。

## 4. 用户角色
- 区域/集团管理者：关注整体趋势、筛选维度对比、异常识别。
- 项目操盘人员：关注具体项目户型结构、趋势表现、明细指标。

## 5. 功能需求

### 5.1 页面导航
- FR-001 系统应默认进入集团看板页。
- FR-002 用户在项目明细或项目搜索中点击项目后，应进入项目详情页。
- FR-003 项目详情页点击返回后，应回到集团看板页。
- FR-004 从看板进入详情时，应透传当前 `period` 与 `propertyType` 作为详情默认筛选值。

### 5.2 看板页顶部筛选
- FR-005 看板页应提供周期切换：`当日 / 当月 / 当年`。
- FR-006 看板页应提供业态切换：`住宅 / 商办 / 车储`。
- FR-007 看板页应提供口径切换：`协议 / 合同`。
- FR-008 任一顶部筛选切换后，概览卡、趋势图、项目明细应同步刷新。

### 5.3 看板页概览与分类筛选
- FR-009 看板页应展示概览指标（套数、金额、环比）。
- FR-010 看板页应支持展开“项目类型筛选”面板。
- FR-011 分类按钮应支持三类：`按销售状态 / 按拿地年份 / 按重点城市`。
- FR-012 分类切换时，应清空当前已选子项。
- FR-013 子项卡片支持点击选中并联动趋势图和项目明细标题/数据。
- FR-014 子项卡片支持横向滑动，并按“最接近容器中心”自动选中。
- FR-015 滑动到最左侧时，应优先选中第一张卡；滑动到最右侧时，应优先选中最后一张卡（如 `2026年拿地`）。
- FR-016 提供“清空筛选”能力，清空后应恢复未筛选状态并收起面板。

### 5.4 看板页趋势图
- FR-017 趋势图标题应随周期变化：`近7日流速趋势 / 近6周流速趋势 / 近6个月流速趋势`。
- FR-018 趋势图应支持指标维度切换：`套数 / 金额`。
- FR-019 当年模式应支持版本对比选择：`年度经营计划版 / 首开定价会版 / 全景会版 / 经营策划会版 / 交底会版`。
- FR-020 趋势图 tooltip 应展示当前点位关键数值；当年模式下应展示目标与差值信息。
- FR-021 当年模式图表区域应支持横向滚动；当日/当月模式默认展示全量可见数据。

### 5.5 看板页项目明细表
- FR-022 项目明细标题应体现当前筛选标签（如已选择分类子项）。
- FR-023 明细表应支持字段筛选，字段包含：`套数、金额、回款现金、回款贷款、回款合计`。
- FR-024 明细表应包含合计行。
- FR-025 明细表应支持按项目点击进入项目详情页。
- FR-026 明细表应支持横向滚动，在多字段场景下不应发生表头表体错位或可视区域溢出。
- FR-027 粘性表头场景下，表头与表体应在同一滚动容器内保持列宽一致。

### 5.6 项目搜索抽屉
- FR-028 点击“搜索”应打开项目搜索抽屉，支持关闭返回。
- FR-029 搜索输入应按项目名称进行包含匹配（不区分大小写）。
- FR-030 搜索结果应实时更新并展示合计行。
- FR-031 搜索结果点击项目应进入项目详情并自动关闭抽屉。
- FR-032 移动端聚焦搜索输入时，不应触发页面异常放大（输入字号不小于 16px）。

### 5.7 项目详情页顶部筛选与户型卡
- FR-033 详情页应提供周期、分期、业态-二级分类、口径筛选。
- FR-034 详情页应展示“全部已售 + 户型卡片”横向列表。
- FR-035 点击户型卡后，趋势图与明细标题/数据应联动更新。
- FR-036 户型卡横向滑动应自动选中中心邻近卡片。
- FR-037 户型卡滑动到最左时，应自动回到“全部已售”。

### 5.8 项目详情页趋势图与明细
- FR-038 详情页趋势图应支持 `套数 / 金额` 切换。
- FR-039 当年模式应支持版本对比切换，并影响目标值展示。
- FR-040 在“全部已售 + 套数”场景下，趋势图应额外展示“来访组数”。
- FR-041 详情页明细表日期列应按时间倒序排列，显示顺序为从左到右“最新到最旧”。
- FR-042 日期区间表头应支持换行显示（如 `2/24` 与 `-3/02` 分两行）。
- FR-043 明细表内容应随当前筛选（口径、指标类型、户型）联动变化。
- FR-044 详情页明细标题应体现当前口径与范围；未下钻时显示全盘明细，选中子项后显示对应子项明细。
- FR-045 详情页明细表第一列应固定为 `指标`，并在表头下方展示单位说明。
- FR-046 协议/合同场景下，明细表默认展示字段应包含：`协议/合同套数、协议/合同金额、回款合计、回款现金、回款按揭`。
- FR-047 来访场景下不展示明细表，仅保留来访趋势图与全盘口径说明。
- FR-048 明细表字段应与趋势图指标口径保持一致；切换 `协议 / 合同` 或 `套数 / 金额` 时，字段名称与数据应同步变化。
- FR-049 明细表内容应随 `周期、分期、业态-二级分类、户型/子项卡片` 联动刷新，且与趋势图展示范围保持一致。
- FR-050 明细表在横向滚动时，应保证首列固定、表头表体对齐，不出现列错位、遮挡或右侧空白溢出。
- FR-051 来访场景下，明细表区域应整体隐藏，不占据页面内容高度。
- FR-052 明细表应支持在移动端横向滚动查看所有日期列，且滚动过程中首列 `指标` 保持可见。
- FR-053 详情页点击“重置”后，明细表应恢复到默认筛选对应的字段、标题、单位与数据状态。

## 6. 非功能需求
- NFR-001 页面应适配移动端主流视口宽度，关键内容可见且可滚动访问。
- NFR-002 所有筛选交互应即时响应，不依赖页面刷新。
- NFR-003 粘性区域（导航、筛选、表头）在滚动时应保持层级正确，不遮挡核心交互。
- NFR-004 图表与表格在数据量变化时不应出现明显布局抖动或重叠。

## 7. 数据与技术约束
- 使用 `dashboardData.ts` 中的 Mock 数据作为当前唯一数据源。
- 前端采用 React + TypeScript + Recharts + Tailwind 风格类名实现。
- 当前阶段不包含后端接口契约、错误码处理、鉴权与审计日志。

## 8. 验收标准（UAT）
- AC-001 切换顶部筛选后，概览/趋势/明细三块数据在同一交互周期内联动更新。
- AC-002 横向滑动分类卡片时，当前选中项会变化，趋势与明细同步更新。
- AC-003 分类卡片能选中首尾项，不会出现“最后一项无法选中”问题。
- AC-004 项目明细在开启多字段时可横向查看完整列，不出现右侧溢出空白遮挡。
- AC-005 移动端打开项目搜索并聚焦输入框时，页面不出现不可恢复的放大状态。
- AC-006 项目详情中，户型卡左滑回起点后可恢复到“全部已售”。
- AC-007 项目详情明细日期为左新右旧，且日期区间换行展示正常。

## 9. 后续扩展（非本期）
- 对接真实后端接口与统一时间口径。
- 增加权限控制与角色化指标可见性。
- 增加导出能力（图表截图、明细导出）。
